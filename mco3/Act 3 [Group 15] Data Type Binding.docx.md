3\. The tables above show the behavior of how a programming language behaves when encountering incompatible types. Discuss your selected language handles type incompatibility. You’re encouraged to use terms discussed in the Type Bindings lesson to articulate your thoughts.

| Language  | How is type incompatibility handled? |
| ----- | :---- |
|  Kotlin | Kotlin uses static and strong type binding. Every variable’s type is fixed at declaration and cannot truly change throughout the program. Type mismatches are caught as early as compile-time errors before the program runs. It also never implicitly coerces one type into another, with any and all conversions requiring explicit function usage (.toInt(), .toDouble(), .toString() among others).   |
| Rust | Static & Strong Typing \- Rust handles type incompatibility aggressively at compile-time. Variables are statically bound to a specific data type upon declaration. If an incompatible literal is assigned, the compiler rejects it immediately. Furthermore, Rust is strongly typed and does not support implicit type coercion; developers must explicitly cast types (e.g., 6.5 as i32 or .to\_string()) to mix data types in assignments or arithmetic operations.  |
| Javascript | Dynamic & Weak Typing \- Javascript uses dynamic type binding, meaning variable types are not fixed and can change at runtime. It handles type incompatibility via weak typing (implicit type coercion). When encountering mismatched types in operations (like a number and a string), Javascript will automatically coerce one type into another (e.g., turning a number into a string for \+ concatenation). While this prevents runtime crashes, it can produce unintended mathematical outputs like NaN during unsupported operations like string subtraction |
| R | R operates via Dynamic Type Binding linked with a Weaker/Implicit Coercion system for numeric primitives, but it is stricter for non-numeric domains. Variable types dynamically shift based on current assignments. When operating on mismatched numbers, it performs implicit upcasting (e.g., smoothly shifting an integer to a double floating point). However, when mixing character vectors (Strings) into math workflows, it lacks default conversion mechanisms and stops with a Runtime Error.  |
